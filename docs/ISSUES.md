## 一、数学与命题

### M1. 端点公式的 period-12 反例在数学上不可能（P0，仍存在）

- **位置**：§3.7 Remark 3.12（`main.tex` 约 319–321 行）。
- **问题**：文中写 `S = ababccccababccccababccccabab` 长度 28，在 `p=12` 时 `LCE(0,12)=18`。但 `n-p=16`，LCE 不可能超过 16；该串也不是周期 12（`S[0]='a'`，`S[12]='c'`）；`X=abab` 的出现位置是 `{0,8,16,24}`，不是 `{10,12}`；实际 `LCE(0,12)=0`。
- **影响**：读者按例子复算会立刻发现错误，直接损害整节可信度。
- **修法**：改用审计给出的极小反例：
  - `U="aaab"`，回文前缀 AP `{2,3}`，`d0=2, p=1`；
  - `V="ab"`；
  - `e = 1 + LCP(U[1..],U) = 3`，`g = LCP(V,Q∞) = 1`；
  - 在 `d=2`：`e-d=1=g`，普通分支给 `ℓ=1`，真实 `LCP(U[2..],V)=2`；
  - 合并语境：`A=rev(U)="baaa"`，`B="ab"`，核 `d=2`，`ℓ_L(2)=2≥n=2`，输出长度 `2n+d=6`，`AB="baaaab"` 是回文；普通公式会算成 4，特殊点修正后为 6。
- **备注**：定理本身（特殊点机制）经 9,734 组穷举 + 34,451 组随机测试支持，**只有例子是错的**。

### M2. §7 的 “identity held in 3000/9952” 自相矛盾（P0，仍存在）

- **位置**：§8（distinct）第 1 段。
- **问题**：
  1. 若 identity 正确，应 9952/9952 成立；3000/9952 恰好说明它**不**成立。
  2. “最长回文后缀唯一”与“创建一个新 eertree 节点”**不等价**；后者取决于该最长回文后缀是否首次出现，而不是“唯一”。
  3. 该段先说 “is correct”，后说 “held in 3000/9952”，逻辑冲突。
- **修法**：改成“该等价在 3000/9952 个测试中失败（即不成立）”，给出失败例子与脚本；或者整节降级为“未验证的开放方向”，删除具体统计。

### M3. §7 的 30/2881、0.25|B|、35% 等数字不可复核（P1，仍存在）

- **位置**：§8 的 δ 段与 runs-summary 段。
- **问题**：这些数字不在已发布的 `notes/` 中，也不在仓库代码/测试里；来源可能是被排除的对话记录。
- **修法**：发布对应脚本与数据，或删除具体数字，只保留定性结论。

### M4. LP-only 通道的 `O(log²)` 论证有算术/层数错误（P0，仍存在）

- **位置**：§5.3（The LP-only channel）。
- **问题**：文中写“若 `d_max < 4n`，整个候选范围长度小于 `2n`，只跨 `O(1)` 个 dyadic 层”。候选范围是 `[1,d_max]`，`d_max<4n` 时长 **<4n**，不是 `<2n`；`[1,4n]` 跨 `Θ(log n)` 层，不是 `O(1)`。
- **修法**：重新证明（例如证明 `best` 足够大，或候选被长度条件大量排除），否则把 LP-only 的 `O(log²)` 降级为“额外假设下/实验观察”。

### M5. batch-LCE 的 `Ω(k log n)` 不是证明，且与论文数据矛盾（P0，仍存在）

- **位置**：§6.2 Barrier 6.2 与其后的段落。
- **问题**：
  1. Steiner 树下界需要形式化模型（允许哪些 grammar 操作、字符访问是否必须走叶子、pattern 是否预处理），文中只有“when the leaves are spread”的说明。
  2. 文中数据 `P_k, n=3071, k=12`：Steiner 树 90，而 `k log n=144`。`90 < 144`，与“Ω(k log n)”直接矛盾。
  3. “ratio 7.5”是 `90/12`（每叶节点数），不是 `90/144`（后者约 0.625）。
  4. 正确的经典界至多是 `Ω(k log(n/k))`；对 `k=Θ(log n)` 仍是 `Ω(log² n)` 量级，但当前表述不成立。
- **修法**：改成 Conjecture/Barrier，写 `Ω(k log(n/k))`，报告 `90 vs 144` 的实际比值并解释；删除“tight in constructions tested”。

### M6. lazy summaries 的“失败”是启发式，不是定理（P1，仍存在）

- **位置**：§6.3。
- **问题**：没有定义势函数、没有证明每个操作必须物化哪些节点、没有排除“只物化查询路径 + 缓存”的方案。`P_11` 的 12.2 个坏节点只是该串+随机优先级下的实验。
- **修法**：降级为 “evidence/heuristic”，或补一个形式化的势函数论证。

### M7. 代价模型是会计模型，不是“紧界”证明（P1，部分修）

- **位置**：§5.1 的 `T=M·(A·c·λ+R)`。
- **问题**：`M,A,c,λ` 的取值是假定/上界；没有证明：
  - 为什么每个节点必须处理 `A` 个 AP；
  - 为什么每个 AP 必须付 `c·λ`（`c` 的下界没有）；
  - 为什么 `M,A,λ` 不能互相折算。
- **v2 状态**：标题/摘要已去掉 “tight”，但 §3.2 仍有 “this upper bound is tight in the worst case”（指 AP 表示，见 M9），需避免误读。
- **修法**：明确写成“在该代价模型下的上界”；只对 `A` 的**表示大小**主张下界。

### M8. “expected O(log²)” 是经验陈述（P1，部分修）

- **位置**：摘要、§5.2。
- **问题**：只给了测量值（1.5–5.6、1.49），没有证明对何种输入分布成立、期望是对输入还是对 Treap 优先级；“in expectation”未定义。
- **修法**：标为 empirical/heuristic；若要严格，给出分布假设与证明。

### M9. `A=Θ(log n)` 是表示下界，不是运行时间下界（P2，仍存在）

- **位置**：§3.9、§6.1、Corollary 3.4 后一句。
- **问题**：`Z_k` 证明的是“精确 AP 划分至少需要 Ω(log n) 组”，不是“任何算法必须做 Ω(log n) 工作”。文中 “tight in the worst case” 容易被读成后者。
- **修法**：统一写成 “representation lower bound”。

### M10. 端点定理的陈述不够精确（P2，仍存在）

- **位置**：Theorem 3.11。
- **问题**：公式写 `T = {p≥n-E_L} if E_R≥n; ∅ if E_R<n`，随后再说 “together with at most one special point”。当 `E_R<n` 时 `T` 并非严格空集，而是 `{p0}∩V` 的子集。
- **修法**：写成 `T = T_base ∪ ({p0}∩V)`，并说明 `p0` 需额外 LCE 验证。

### M11. 哈希误差界仍是粗略量级（P2，部分修）

- **位置**：§5.4。
- **问题**：`K=O(n log³n+q log⁴n)` 是保守会计；未处理自适应操作序列、底数选择、不同长度字符串的碰撞界细节。
- **修法**：明确 “heuristic bound”，或给出标准多项式哈希的严格条件（非自适应、随机底数）。

### M12. `P_k` 构造的通用性（P2，待验证）

- **位置**：Proposition 3.14。
- **问题**：审计只验证到 `k≤9`；一般 `k` 的陈述需要完整归纳（目前是命题而非定理）。
- **修法**：补完整归纳证明，或写成“对小 k 验证 + 一般构造”。

## 二、模型与数据结构

### D1. V3 的 LCE 原语不存在（P0，部分修）

- **位置**：§1.2 变体表、§4.5、§5.3。
- **问题**：`O(log³)` 的全操作集版本依赖一个支持区间翻转/循环移位的 `O(log n)` 动态 LCE；GKK/DK24 不提供。
- **v2 状态**：已明确分成 V1/V2/V3，这是正确的；但 V3 仍是**条件结论**，不是定理。
- **修法**：二选一：
  1. 把论文定位为 V1/V2（全域 `O(log⁴)`，点编辑 `O(log³)`）；
  2. 设计/引用一个支持翻转的动态 LCE，补齐 V3。

### D2. 合并公式需要 `LCP(rev(A)[d..],B)`，单一 GKK 结构不提供（P0，仍存在）

- **位置**：§2.3、§4.2、§5.1。
- **问题**：跨界合并同时需要正向和反向的 LCE。GKK 是单一动态文本的 LCE；论文没有说明如何维护反向文本结构、如何与 Treap 的编辑同步。
- **影响**：即使不考虑“翻转操作”，仅合并本身就需要反向 LCE；这是比 V3 更基础的模型缺口。
- **修法**：
  - V2（无翻转）：同时维护 `S` 与 `rev(S)` 两个 GKK 结构，点编辑时同步镜像；明确写出同步代价与正确性。
  - V3（有翻转）：需要可逆/可分裂合并的动态 LCE，或改用哈希 LCE（回到 V1）。

### D3. Treap 的 `build()` 优先级不是随机的（P1，仍存在）

- **位置**：`code/experimental_treap_ap.cpp` 的 `build()`（约 453 行）。
- **问题**：`priorityValue[v] = max(left,right)+1` 得到确定性高度树；`newNode()` 用 32-bit 随机优先级。两者混用后，点更新插入的随机节点可能频繁成为新根，不再是论文声称的“随机优先级 Treap”；期望深度分析不能直接套用。
- **修法**：`build()` 也用同一随机生成器；或改用 AVL/红黑树并明确不宣称 Treap 随机性。

### D4. 参考实现不支持插入/删除（P1，仍存在）

- **位置**：§7.2 与 `experimental_treap_ap.cpp` 输入格式。
- **问题**：实现只有赋值、翻转、循环移位、查询；论文框架宣称 insertion/deletion。v2 已注明“不实现”，但读者容易把“框架支持”误读为“实现支持”。
- **修法**：补实现与对拍，或在摘要/贡献里明确“实现仅覆盖 V1 的四类操作”。

### D5. `MAXNODE=400000` 固定数组、不回收节点（P2，仍存在）

- **位置**：`experimental_treap_ap.cpp`。
- **问题**：每次点更新 `nodeCount+1`，旧节点不回收；`n+q>400000` 会越界。
- **修法**：动态分配/节点池回收，或明确规模上限。

### D6. 哈希 LCE 的复杂度与主定理不一致（P2，已修）

- **位置**：§4.5、§7.2。
- **问题**：实现是二分 + 区间哈希，单次 LCE `O(log² n)`，对应 V1 `O(log⁴ n)`；旧稿把它与 V2 的 `O(log³ n)` 混在一起。
- **v2 状态**：已用 V1/V2 区分；保留记录。

### D7. 懒反转与哈希/LCE 的一致性未验证（P1，仍存在）

- **位置**：§4.3、`experimental_treap_ap.cpp` 的 `applyReverse`。
- **问题**：区间翻转后，LCE/哈希查询必须先下推反转标记；代码与测试是否覆盖“翻转后再做跨界合并”未说明。
- **修法**：补针对性测试（翻转区间跨越合并点、翻转后查询、连续翻转）。

### D8. 区间查询的“提取-查询-合回”未做端到端验证（P2，待验证）

- **位置**：§4.3。
- **问题**：区间查询需要把目标区间拆成临时树，查询后按原顺序合回；实现只支持全串查询。
- **修法**：补区间查询实现与对拍，或明确论文只讨论全串查询。
