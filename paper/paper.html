Fully Dynamic Longest Palindromic Substring via Mergeable Palindrome Summaries

Abstract. We study the longest palindromic substring (LPS) problem for a string that undergoes point updates, insertions, deletions, range reversals, range cyclic shifts, and interval LPS queries. We develop a mergeable-summary framework: an implicit Treap stores the sequence, and every node keeps the longest palindrome length LP\operatorname{LP}, the palindromic-suffix and palindromic-prefix length sets PSuf\operatorname{PSuf} and PPref\operatorname{PPref} compressed as arithmetic progressions, and forward/reverse hashes. The combinatorial heart is fourfold: a dyadic-layer lemma showing that palindromic suffix lengths in each layer [L,2L)[L,2L) form an arithmetic progression; a periodic-family LCE lemma answering all extension queries of one progression with O(1)O(1) LCE calls; a five-candidate lemma for the crossing maximum; and an endpoint formula for the short-kernel region that handles the equality boundary correctly. These give a merge rule in which the per-node cost is M⋅(A⋅c⋅λ+R)M\cdot(A\cdot c\cdot\lambda+R), with M=O(log⁡n)M=O(\log n) Treap depth, A=O(log⁡n)A=O(\log n) progressions per summary, c=O(1)c=O(1) LCEs per progression, and λ\lambda the cost of one dynamic LCE.

Our complexity statements are deliberately split into three variants. (V1) With LCE answered by binary search over Treap hashes, the full operation set runs in O(log⁡4n)O(\log^4 n) per operation with high probability, unconditionally in the data-structural sense and Monte Carlo only because of hashing. (V2) With the dynamic LCE of Gawrychowski–Karczmarz–Kociumaka–Łacki–Sankowski (GKK), which supports point updates, insertions, and deletions in O(log⁡n)O(\log n) time, those operations and interval queries run in O(log⁡3n)O(\log^3 n) with high probability. (V3) The same O(log⁡3n)O(\log^3 n) bound for range reversal and cyclic shift is conditional on an LCE oracle supporting those rearrangements; the cited GKK and Duyster–Kociumaka primitives do not provide one. We state this gap explicitly instead of attributing the two bounds to one algorithm.

We further prove that the number of progressions per summary is Θ(log⁡n)\Theta(\log n) on the explicit family ZkZ_k, analyze why a batch-LCE primitive that would collapse A⋅λA\cdot\lambda is not available in the recompression parse-tree model, and explain why lazy summaries do not give an amortized improvement. These are barriers within the framework, not lower bounds for the dynamic LPS problem. Finally, we report exhaustive and randomized verification of every merge formula (hundreds of thousands of cases, zero failures), an experimental Treap implementation, and an independent block-decomposition implementation with reproducible differential testing. The block implementation is correct on the saved battery but empirically slower than per-query Manacher at the tested sizes; we report this negative result. The distinct-palindromic-substring extension is treated in a separate exploratory section with explicit negative findings. The paper therefore states not only what the framework achieves, but also exactly which steps are proved, which are verified, which are assumed, and which remain open.

Introduction

Problem and model

Let SS be a string over an alphabet Σ\Sigma, whose current length is nn. We consider the following operations, each specified by an interval in the current string:

  1. point update: replace S[p]S[p] by a given character;

  2. insertion and deletion: insert a character at position pp, or delete S[p]S[p];

  3. range reversal: replace S[l..r)S[l..r) by its reversal;

  4. range cyclic shift: rotate S[l..r)S[l..r) cyclically by kk positions;

  5. LPS query: return the length of a longest palindromic substring of the whole string, or of a queried interval S[l..r)S[l..r).

The goal is a data structure with q⋅polylog⁡(n+q)q\cdot\operatorname{polylog}(n+q) total time for any sequence of qq operations, in the regime where each operation may change the text.

Results at a glance

We work inside the following mergeable-summary framework. An implicit Treap with random priorities stores the sequence. Each node stores a summary of its substring: its length, forward and reverse hashes, LP\operatorname{LP}, and the sets PSuf⁡,PPref\operatorname{PSuf},\operatorname{PPref} represented as O(log⁡n)O(\log n) arithmetic progressions (APs). Split and merge recompute the summaries along the affected paths. LCE queries are answered either inside the Treap by hashing, or by an external dynamic-string oracle.

The complexity depends on which LCE mechanism is used, and on which rearrangements the oracle supports. We therefore state three variants.

V1 binary search over Treap hashes, O(log⁡2n)O(\log^2 n) per LCE all of (i)–(v) O(log⁡4n)O(\log^4 n) whp\mathrm{whp}
V2 GKK dynamic LCE, O(log⁡n)O(\log n) whp\mathrm{whp} (i), (ii), (v); no reversal or rotation O(log⁡3n)O(\log^3 n) whp\mathrm{whp}
V3 hypothetical LCE oracle of O(log⁡n)O(\log n) supporting reversals and rotations all of (i)–(v) O(log⁡3n)O(\log^3 n) whp\mathrm{whp} (conditional)

Variant V1 is the bound realized by the reference implementation: it needs no external dynamic-string structure, but each LCE costs a binary search over hash comparisons, and each hash comparison costs a tree traversal, so λ=O(log⁡2n)\lambda=O(\log^2 n) and the total is O(log⁡4n)O(\log^4 n). Variant V2 uses the GKK dynamic string, which supports point updates, insertions and deletions with O(log⁡n)O(\log n) updates and LCE queries; range reversal and cyclic shift are not operations of that structure. Variant V3 is the natural target of the framework, but the required oracle is not provided by the literature we are aware of; we keep it as an explicit condition rather than a theorem.

The expected/typical behaviour is better. On random inputs the number of APs per summary is a small constant in experiments, so V2 becomes O(log⁡2n)O(\log^2 n) in expectation. For whole-string LPS only, the long-kernel AP count drops to O(1)O(1) by LP pruning, and the expected bound is again O(log⁡2n)O(\log^2 n); this channel cannot replace the full summary for interval queries.

Positioning

The closest prior work is Amir and Boneh [AB19], who maintain the LPS under single-character substitutions in O(log⁡4n)O(\log^4 n) time with high probability (randomized LCE) or O(log⁡5nlog⁡*n)O(\log^5 n\log^*n) time (deterministic LCE). Their model is narrower than ours, and their analysis is the benchmark for the substitution-only case. Amir, Charalampopoulos, Pissis, and Radoszewski [ACPR19] give the first sublinear fully dynamic algorithm for longest common substring; their techniques also yield a fully dynamic LPS with Õ(n)\tilde O(\sqrt n) time in the one-sided edit setting (and Õ(n2/3)\tilde O(n^{2/3}) for two strings). Funakoshi, Nakashima, Inenaga, Bannai, and Takeda [FNIBT21] solve a different problem: the string is preprocessed once, and the LPS is reported after a single edit that is treated as a query; their query time is O(log⁡log⁡n)O(\log\log n) after O(n)O(n) preprocessing, but the string itself does not evolve. Dynamic LCS has a polylogarithmic algorithm [CGP20] and a lower bound of Ω(log⁡n/log⁡log⁡n)\Omega(\log n/\log\log n); it is the closest dynamic-string analogue of the present work.

Our contribution is not a new lower bound for dynamic LPS and not the first polylogarithmic dynamic palindrome result—that is [AB19] for substitutions. It is a mergeable-summary route that supports a wider operation set, together with a careful account of the cost of each ingredient. The O(log⁡3n)O(\log^3 n) bound of V2 is one logarithmic factor better than [AB19] in the substitution-only case, but only under a randomized LCE oracle; the deterministic bound of [AB19] remains stronger in the deterministic model. We do not claim a breakthrough.

Preliminaries

Strings and notation

Intervals are half-open. For a string XX, rev⁡(X)\operatorname{rev}(X) denotes its reversal, |X||X| its length, and LCP⁡(X[i..],Y[j..])\operatorname{LCP}(X[i..],Y[j..]) the length of the longest common prefix of the two suffixes; we write LCE⁡(X,i,Y,j)\operatorname{LCE}(X,i,Y,j) for the same quantity. For a string XX of length mm, PSuf⁡(X)={d∈[1,m]:X[m−d..m) is a palindrome},PPref⁡(X)={d∈[1,m]:X[0..d) is a palindrome}.\operatorname{PSuf}(X)=\{\,d\in[1,m]: X[m-d..m)\text{ is a palindrome}\,\},\qquad \operatorname{PPref}(X)=\{\,d\in[1,m]: X[0..d)\text{ is a palindrome}\,\}. Both sets are stored in increasing order. An arithmetic progression (AP) is a finite set a,a+p,a+2p,…,a+(t−1)p,p>0,a,\ a+p,\ a+2p,\ \ldots,\ a+(t-1)p,\qquad p>0, of t≥1t\ge1 terms; a singleton is an AP with t=1t=1 and arbitrary step. An AP intersected with an integer interval is again an AP or empty.

Dynamic-string primitives

We use two external results as black boxes.

Definition 2.1 (Dynamic LCE oracle).

A dynamic LCE oracle maintains a text under a set of updates 𝒰\mathcal U and supports LCE⁡(X,i,X,j)\operatorname{LCE}(X,i,X,j) on the current text. We say it is (u,λ)(u,\lambda)-efficient if every update in 𝒰\mathcal U costs O(u)O(u) and every LCE query costs O(λ)O(\lambda) in the word RAM, with high probability when randomized.

The GKK structure [GKK18] is (O(log⁡n),O(log⁡n))(O(\log n),O(\log n))-efficient for 𝒰\mathcal U consisting of point substitutions, insertions, and deletions. The Duyster–Kociumaka result [DK24] answers internal pattern matching (IPM) queries on a balanced recompression-based RLSLP, and in particular on top of [GKK18], in O(log⁡n)O(\log n) time: given fragments X,YX,Y of the current text with |Y|<2|X||Y|<2|X|, it reports all occurrences of XX in YY as O(1)O(1) APs. Neither primitive lists range reversal or cyclic shift as a supported update. This is the source of the V2/V3 distinction.

When no external oracle is used, LCE can be answered inside the Treap: store forward and reverse polynomial hashes at every node, compare two substrings by extracting their hashes, and binary search for the longest matching prefix. A hash extraction costs O(log⁡n)O(\log n) (a tree path), and the binary search performs O(log⁡n)O(\log n) extractions, so λ=O(log⁡2n)\lambda=O(\log^2 n). This is the mechanism of V1.

The Treap

An implicit Treap stores a sequence in inorder. Each node has a random priority, a subtree size, and a summary of the substring it spans. Split and merge are the standard randomized operations; both take O(log⁡n)O(\log n) expected time, and both recompute the summaries of the nodes they visit. With high probability the depth is O(log⁡n)O(\log n). A reversal of an interval is implemented by splitting out the interval, toggling a lazy reversal flag at its root, and merging back; the flag swaps forward and reverse hashes and exchanges PSuf\operatorname{PSuf} with PPref\operatorname{PPref}, while LP\operatorname{LP} is invariant. A cyclic shift is implemented by splitting the interval into two parts and merging them in the opposite order. Insertions and deletions are a split followed by a merge.

A range LPS query isolates S[l..r)S[l..r) as a temporary tree by two splits, reads the LP\operatorname{LP} stored at its root, and merges the pieces back. A whole-string query reads the LP\operatorname{LP} at the root.

Every palindromic substring of ABAB is either entirely inside AA, entirely inside BB, or has the following form: it consists of a palindromic core WW adjacent to the concatenation point, extended symmetrically on both sides. Consequently

Dyadic layers

Lemma 3.2 (Dyadic AP lemma).

For every dyadic layer [L,2L)[L,2L), the palindromic suffix lengths of a string lying in that layer form a contiguous arithmetic progression whose common difference is the minimal period of the longest palindromic suffix of that layer. The same holds for palindromic prefixes.

Proof.

Let ww be the longest palindromic suffix in the layer and W=|w|W=|w|, so L≤W<2LL\le W<2L and L>W/2L>W/2. Let vv be another palindromic suffix in the layer, V=|v|≤WV=|v|\le W. Since v,wv,w are suffixes of the same string and V≤WV\le W, vv is a suffix of ww; since both are palindromes, vv is also a prefix of ww, hence a border of ww. Put q=W−Vq=W-V. Then qq is a period of ww, and q≤W−L<W/2q\le W-L<W/2. Let pp be the minimal positive period of ww; then p≤qp\le q, so p+q<W≤W+gcd⁡(p,q).p+q<W\le W+\gcd(p,q). By Fine–Wilf [FW65], gcd⁡(p,q)\gcd(p,q) is a period of ww; minimality of pp gives p=gcd⁡(p,q)p=\gcd(p,q), hence p∣qp\mid q. Conversely, every multiple kp<Wkp<W is a period, so W−kpW-kp is a border of ww; a border of a palindrome is a palindrome, so each W−kp≥LW-kp\ge L is a palindromic suffix length. Hence the layer set is {W−kp:W−kp≥L}\{W-kp: W-kp\ge L\}, an AP. Reversing the string gives the prefix statement. The hypothesis L>W/2L>W/2 is essential and follows from W<2LW<2L. ◼\blacksquare

Remark 3.3.

The AP structure of palindromic suffixes is the series-link property of the eertree [RS15]; Lemma 3.2 is a dyadic-layer restatement with a self-contained proof. We use the dyadic form because it composes cleanly with Treap summaries. This is not a new combinatorial discovery, and the paper does not claim it as one.

The data structure

Node summary and invariants

Each node vv spanning a substring SvS_v stores:

  • |Sv||S_v| and the subtree size;

  • forward and reverse polynomial hashes of SvS_v;

  • Lv=LP⁡(Sv)L_v=\operatorname{LP}(S_v);

  • the AP lists Pv=PSuf⁡(Sv)P_v=\operatorname{PSuf}(S_v) and Qv=PPref⁡(Sv)Q_v=\operatorname{PPref}(S_v);

  • a lazy reversal bit.

The summary invariant is that these fields are exactly the quantities defined for SvS_v in the current orientation. A reversal flag at vv means that the logical string is rev⁡(Sv)\operatorname{rev}(S_v); the stored hashes are swapped and Pv,QvP_v,Q_v exchanged when the flag is applied, so the invariant is maintained.

Merging two children

  1. Internal answers. L=max⁡(Lleft,Lright,CL,CR)L=\max(L_{\mathrm{left}},L_{\mathrm{right}},C_L,C_R), using (1) on the two children.

  2. Left crossing. For each AP of PSuf⁡(A)\operatorname{PSuf}(A), compute ee and gg by Lemma 3.5, evaluate the five candidates of Lemma 3.7, and keep the maximum. For the short-kernel part, use the endpoint formula of Theorem 3.11.

  3. Right crossing. Symmetrically, using PPref⁡(B)\operatorname{PPref}(B) and the reversed orientation.

  4. Suffix and prefix lists. Generate the four ranges of Table 1 from PSuf⁡(B)\operatorname{PSuf}(B), PPref⁡(B)\operatorname{PPref}(B), the empty core, and the filtered PSuf⁡(A)\operatorname{PSuf}(A); merge adjacent APs into the dyadic representation. Generate PPref⁡(AB)\operatorname{PPref}(AB) symmetrically.

  5. Hashes. Concatenate the forward and reverse hashes.

The two crossing evaluations share the per-AP preprocessing: the pair (rev⁡(A),B,PSuf⁡(A))(\operatorname{rev}(A),B,\operatorname{PSuf}(A)) and its mirror each compute ee and gg once per AP. The archived implementation measures a reduction of about 42%42\% in LCE calls from this sharing.

Operations

A point update is two splits and two merges. An insertion or deletion is the same with a length change. A reversal is three splits, a flag toggle, and three merges. A cyclic shift is four splits and four merges in the rotated order. A whole-string query reads the root; an interval query is two splits, a read, and two merges. Since each split/merge visits O(log⁡n)O(\log n) nodes and each node merge is charged in Section 5, the operation costs follow.

Correctness

Theorem 4.1 (Correctness).

Assume LCE queries are answered exactly. Then every operation preserves the summary invariant, and every LPS query returns the length of a longest palindromic substring of the requested fragment.

Proof.

The proof is by induction on the structure of the Treap and on the operation sequence. For a leaf, the summary is trivially correct. For an internal node with children A,BA,B, Theorem 3.10 gives exactly the suffix and prefix sets of ABAB, and Lemma 3.1 gives exactly the crossing maximum; the internal maxima are the children’s by induction. Hence the parent summary is correct. Split and merge preserve the inorder sequence and recompute the summaries along the visited paths, so the invariant is restored. A reversal toggles the flag; the identity PSuf⁡(rev⁡(X))=PPref⁡(X)\operatorname{PSuf}(\operatorname{rev}(X))=\operatorname{PPref}(X) and the hash swap preserve the summary. A cyclic shift is a composition of splits and merges. A query reads a summary that, by the invariant, stores the exact LPS length of the isolated fragment. ◼\blacksquare

The theorem is conditional on exact LCE. With hashing, it holds except with the collision probability analyzed in Section 5.4; with an external oracle, it holds except for the oracle’s failure probability.

LCE variants and their cost

V1 (Treap hashing). A hash of a fragment is extracted in O(log⁡n)O(\log n) by a path traversal; an LCE is a binary search over O(log⁡n)O(\log n) such extractions, so λ=O(log⁡2n)\lambda=O(\log^2 n). This variant supports every operation of the model, including reversal and rotation, because the hashes are maintained by the Treap itself.

V2 (GKK). The GKK oracle supports point substitutions, insertions, and deletions in O(log⁡n)O(\log n) per update, and answers LCE in O(log⁡n)O(\log n) whp. It does not list range reversal or cyclic shift among its updates. Using it gives λ=O(log⁡n)\lambda=O(\log n) and the stronger bound, but only for the operations the oracle supports.

V3 (conditional). If an oracle with the same efficiency supported range reversal and cyclic shift, the stronger bound would extend to the full operation set. No such oracle is provided by [GKK18, DK24], and we do not assume one.

Remark 5.4 (What is unconditional).

The combinatorial data structure and its correctness are unconditional (given exact LCE). The complexity separation is the only conditional part. V1 is the safe universal statement; V2 is the strong statement for the edit-only model; V3 is the target for the full model, explicitly conditional.

Barriers within the framework

These results explain why the framework does not improve further. None of them is a lower bound for the dynamic LPS problem in general.

The AP count

Theorem 3.13 gives A=Θ(log⁡n)A=\Theta(\log n) in the worst case. The lower bound is unconditional for exact AP partitions of the palindromic suffix set; it does not depend on the Treap or on the merge algorithm. It rules out any exact summary that stores the full set as APs with fewer groups.

Batch LCE

The product A⋅λA\cdot\lambda could be collapsed only by a primitive that answers many LCEs at once.

Definition 6.1 (Dynamic batch LCE).

Given a dynamic text UU in RLSLP representation, a pattern PP, and positions d1<⋯<dkd_1<\cdots<d_k with k=O(log⁡n)k=O(\log n), report all LCP⁡(U[dt..],P)\operatorname{LCP}(U[d_t..],P) in O(log⁡n)O(\log n) total time.

Barrier 6.2 (Batch-LCE barrier, conditional).

In the recompression parse-tree model, answering LCP⁡(U[dt..],P)\operatorname{LCP}(U[d_t..],P) requires reaching the leaf dtd_t even when the answer is 00, since one must confirm U[dt]≠P[0]U[d_t]\ne P[0]. If the leaves are spread, any algorithm visits their Steiner tree, which has Ω(klog⁡n)\Omega(k\log n) nodes in the constructions tested. Under this model, no batch-LCE primitive achieves O(log⁡n)O(\log n) total time.

The word “barrier” is deliberate: the leaf-access argument is a model-specific obstruction, not a general lower bound, and the Steiner-tree sizes are supported by experiments rather than a proof. For PkP_k at n=3071n=3071 the layer representatives span 9090 nodes against klog⁡n=144k\log n=144 (ratio 7.57.5); for the Fibonacci word at n=6765n=6765, 7878 against 130130 (ratio 7.87.8). Explicit instances with non-aligned representatives give ratios between 1.671.67 and 5.755.75. Thus A⋅λ=Ω(log⁡2n)A\cdot\lambda=\Omega(\log^2 n) in this model, and the batch-LCE route is closed there.

Lazy summaries

Storing only LP\operatorname{LP} and materializing PSuf\operatorname{PSuf} on demand does not give an amortized improvement. The root and the upper layers must be materialized on every operation; materializing a node costs Θ(log⁡2|v|)\Theta(\log^2|v|), while the potential released by deferring it is at most log⁡|v|\log|v|, leaving a logarithmic gap. The PkP_k experiments are consistent with this: for P11P_{11} at n=6143n=6143 with 200200 random priority assignments, the number of bad nodes (at least five APs) on a root-to-leaf path averages 12.212.2 and reaches 2020, close to log⁡n\log n on every operation. The adversary controls the string content, not the priorities, and content alone makes the upper layers bad.

What this does not prove

We do not prove that dynamic LPS with insertions and deletions requires log⁡3n\log^3 n time, nor that q⋅polylog⁡nq\cdot\operatorname{polylog} n is impossible. The barriers are relative to the mergeable-summary framework and to the stated LCE model. A genuine lower bound would need to argue about all data structures, not just this one.

On the test machine, the block implementation is slower than per-query linear Manacher at the tested sizes, for example n=200,000n=200{,}000 with 500500 modifications: 3.83.8 seconds versus 1.41.4 seconds. The asymptotic bookkeeping does not imply a practical advantage, and the block implementation is not a q⋅polylog⁡nq\cdot\operatorname{polylog} n algorithm.

Threats to validity

The tests are finite; they cannot establish the universal quantifiers in the lemmas. The Treap implementation is Monte Carlo and incomplete for insertion/deletion. The block implementation is deterministic but does not realize the mergeable-summary framework. The performance measurements are single-machine and not a benchmark. None of the experiments tests the V3 hypothesis, because no suitable LCE oracle is implemented.

An exploratory extension: distinct palindromes

The archive also studies counting distinct palindromic substrings, globally and per interval: D(S)=|{P:P is a palindromic substring of S}|,D(S[l..r))=|{P:P is a palindrome occurring entirely inside S[l..r)}|.D(S)=\bigl|\{P:\ P\text{ is a palindromic substring of }S\}\bigr|,\qquad D(S[l..r))=\bigl|\{P:\ P\text{ is a palindrome occurring entirely inside }S[l..r)\}\bigr|. The length-based summary compresses lengths, not content equivalence classes or occurrence sets. For S=ABS=AB, the correct merge is D(AB)=D(A)+D(B)+|𝒫cross\(𝒫A∪𝒫B)|,D(AB)=D(A)+D(B)+\bigl|\mathcal P_{\mathrm{cross}}\setminus(\mathcal P_A\cup\mathcal P_B)\bigr|, whose correction term is a content-level membership test that the current summary cannot answer: a palindrome may occur in AA, in BB, and again as a crossing palindrome, and two different APs may carry the same content at different positions.

The additive δ\delta route fails.

Writing distinct(S)=∑iδS(i)\mathrm{distinct}(S)=\sum_i\delta_S(i), where δS(i)\delta_S(i) indicates that the longest palindromic suffix of S[0..i]S[0..i] is unique (equivalently, that position ii creates a new eertree node), is correct; the identity held in 3000/99523000/9952 tested cases. There is a useful asymmetry: δ\delta values inside AA never change, so only BB must be corrected. However, δ\delta rose in 3030 cases and fell in 28812881 cases, with about 0.25|B|0.25|B| changed positions on average. The correction is linear, not polylogarithmic. The rises are new crossing palindromes; the falls are exactly the containment problem. The δ\delta representation relocates the difficulty rather than removing it.

The runs-summary proposal.

A more structural idea is to replace the global PSuf⁡/PPref\operatorname{PSuf}/\operatorname{PPref} granularity by run-level granularity. The runs of ABAB are the union of the runs of AA and BB plus O(1)O(1) boundary merges; within a maximal run of period pp, the palindromic contents are determined by the palindromic prefix and suffix length APs (difference pp); two runs overlap in content only when their periods and phases are compatible, in which case deduplication is a union of length intervals; the boundary-expansion case is exactly the crossing lemmas. If these facts hold, distinctness becomes |⋃RPal(R)||\bigcup_R \mathrm{Pal}(R)|, computable by phase grouping and interval union. The proposal is unverified: the five checks (runs concatenation, Pal(R)\mathrm{Pal}(R) characterization, deduplication lemma, global reconstruction, dynamic behavior under reversal and rotation) were not completed. An earlier experiment reporting 35%35\% support used the wrong question (all occurrences in a single run); the corrected question, deduplication between same-phase runs, was not tested.

Feasibility.

Maintaining repeated-palindrome counts inside the framework is feasible. Maintaining global distinct counts requires a new content-deduplication lemma. Interval distinct counts additionally require an occurrence index supporting Occ⁡(P)∩[l,r−|P|]≠⌀\operatorname{Occ}(P)\cap[l,r-|P|]\neq\varnothing. Full online interval distinct under the complete operation set is an independent research problem. The realistic engineering route is square-root decomposition with local eertrees and a canonical-ID dictionary, at O(npolylog⁡n)O(\sqrt n\operatorname{polylog} n) per operation, not a log⁡3n\log^3 n guarantee.

The comparison with [AB19] must be read carefully. Their algorithm is deterministic given a deterministic LCE structure; with randomized LCE it becomes Monte Carlo with O(log⁡4n)O(\log^4 n) time. Our V2 is Monte Carlo with O(log⁡3n)O(\log^3 n) time for a wider operation set (excluding reversal and rotation), so it is one logarithmic factor better in the randomized model but not in the deterministic model. Our V1 is O(log⁡4n)O(\log^4 n) and supports the full operation set; it matches the randomized bound of [AB19] while covering more operations. We do not claim to dominate the deterministic result.

The dynamic LCS line [ACPR19, CGP20] is the closest technical relative. [CGP20] achieves O(log⁡7n)O(\log^7 n) amortized update time with high probability using the GKK parsing and a lower bound of Ω(log⁡n/log⁡log⁡n)\Omega(\log n/\log\log n); it shows that polylogarithmic dynamic substring problems are attainable with these tools. The present work is a palindrome-specific summary layer on top of the same family of primitives. The one-edit query model [FNIBT21] is different: the text is fixed and an edit is a query, so an O(log⁡log⁡n)O(\log\log n) query time is not comparable to a fully dynamic update time.

The eertree and its series links [RS15] supply the AP structure of palindromic suffixes; the double-ended variant [WYZ25] supports two-ended updates and distinct counting but not arbitrary interior edits, reversals, or rotations. Limitations and open problems

  1. The V3 oracle. The full operation set with O(log⁡3n)O(\log^3 n) requires a dynamic LCE oracle supporting range reversal and cyclic shift. No such oracle is known to us; constructing one, or showing that the Treap’s own hashes can be made to answer LCE in O(log⁡n)O(\log n) amortized, is the main open technical question.

  2. A true lower bound. The barriers are framework-relative. A lower bound for dynamic LPS with insertions and deletions, even under a restricted model, would be a significant result; the dynamic LCS lower bound [CGP20] is the model to emulate.

  3. Batch LCE. Barrier 6.2 is conditional on the parse-tree model and on the Steiner-tree experiments. A formal lower bound, or a counterexample structure, is open.

  4. Lazy summaries. The potential gap is a proof sketch, not a theorem; a stronger invariant might close it.

  5. Wide-fanout trees. A non-binary tree could reduce MM, but summary merging at a wide node becomes more expensive; unexplored.

  6. Distinct palindromes. The content-level deduplication lemma, the canonical-ID compression of a periodic family, and the occurrence index are all open.

  7. Deterministic LCE. V1 is Monte Carlo; a deterministic dynamic LCE with O(log⁡n)O(\log n) updates and queries would remove the hashing caveat. The deterministic LCE of [AB19] has larger logarithmic factors.

  8. The minimal-AP question. The dyadic representation is a valid exact representation, but it is not always the minimum-size AP partition; the exact complexity of minimum fusion is open and was not used in the algorithm.

Conclusion

The mergeable-summary framework gives a clean combinatorial route to fully dynamic LPS: dyadic AP summaries, a periodic-family LCE lemma, five candidates per AP, and an endpoint formula for the short-kernel region. Its self-contained hashing version runs in O(log⁡4n)O(\log^4 n) per operation for the full operation set; its GKK-based version runs in O(log⁡3n)O(\log^3 n) for point updates, insertions, deletions, and interval queries. The O(log⁡3n)O(\log^3 n) bound for range reversal and cyclic shift is conditional on an LCE oracle that the cited literature does not provide, and we state this rather than hiding it. The AP count is Θ(log⁡n)\Theta(\log n) on explicit families, the batch-LCE primitive is unavailable in the recompression model, and lazy summaries do not amortize. The merge formulas are proved and extensively verified; the implementations are documented with their limits, including a negative performance result. The distinct-palindrome extension remains open. The value of the framework is therefore not a single headline bound, but a precise map of what works, what is assumed, and what would be needed to go further.
